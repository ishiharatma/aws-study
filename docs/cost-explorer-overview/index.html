AWS Cost Explorer は、AWS の利用コストと使用量をグラフと表で可視化し、対話的に分析するためのツールです。「どのサービスに」「どのアカウントで」「どのリージョンで」いくらかかっているのかを、期間や切り口を変えながら分析できます。

参照できる範囲は、既定で過去 13 か月分の実績、当月の発生済みコスト、そして今後 18 か月分の予測です（月次であれば、設定により最大 38 か月前まで遡れます）。マネジメントコンソールでの表示は無料で、後述する時間単位・リソースレベルのデータと API 呼び出しのみ課金対象になります。

2.1. Cost Explorer を有効にする

Cost Explorer は、コスト管理コンソールで一度開くと有効になります。有効化した直後は履歴データの準備に数日かかり、当月分のデータはおよそ 24 時間後に参照できるようになります。以降、データは少なくとも 24 時間に 1 回更新されます。なお、一度有効化すると無効化はできません。

Cost Explorer を有効にする

AWS Organizations を使っている場合、Cost Explorer は管理アカウント（支払いアカウント）で有効にすると、メンバーアカウントを含む組織全体のコストを扱えます。メンバーアカウント側の利用可否は、管理アカウントの設定で制御します。

2.2. IAM ユーザー/ロールにアクセスを許可する

AWS アカウントを作成した直後は、ルートユーザーしか請求情報を参照できません。IAM ユーザーや IAM ロールからのアクセスさせるには、ルートユーザーでサインインし、アカウント設定の「IAM ユーザー/ロールによる請求情報へのアクセス」を有効化します。そのうえで、対象の IAM ユーザーやロールに Cost Explorer 用のアクセス許可（ce: で始まるアクション）を付与します。

3.1. 画面の構成とレポートの見方

Cost Explorer のレポート画面は、上部のグラフと下部の明細表、右側のコントロールパネルで構成されます。分析の起点になるのは、次の 4 つの設定です。

設定項目

役割

期間（Date Range）

分析対象の開始日と終了日。過去 6 か月、年初来、カスタム範囲などから選ぶ

粒度（Granularity）

集計単位。月別・日別が標準で、時間別は別途有効化が必要

グループ化（Group by）

グラフの積み上げを分ける軸。サービス別、アカウント別、タグ別など

フィルター（Filters）

特定のサービスやアカウントなどに表示を絞り込む

グラフのスタイルは、棒グラフ、積み上げ棒グラフ、線グラフから選べます。グループ化を「サービス」にすると、サービス別のコスト内訳と増減の傾向がつかめます。そこから「先月だけコストが増加しているサービス」をフィルターで絞り、さらにアカウントや使用タイプでグループ化し直す、という流れで原因を掘り下げていきます。

まずは、次の手順を試すのが分かりやすいです。

  1. 期間を「過去 6 か月」、粒度を「月別」にする
  2. グループ化を「サービス」にして、コストの大きいサービスを確認する
  3. 気になるサービスをフィルターで絞り、グループ化を「使用タイプ」に変えて内訳を見る

Cost Explorer レポートを使用してコストを把握する

3.2. フィルターとグループ化で深掘りする

フィルターとグループ化で指定できる軸（ディメンション）には、次のようなものがあります。

  • サービス、連結アカウント、リージョン、アベイラビリティゾーン
  • インスタンスタイプ、使用タイプ、使用タイプグループ、API 操作
  • 購入オプション（オンデマンド、Savings Plans、スポットなど）、テナンシー
  • コスト配分タグ、コストカテゴリ

コスト配分タグを軸にするには、事前に請求コンソールでタグ キーを有効化しておく必要があります。タグを付けただけでは Cost Explorer に表示されず、有効化の反映にも最大 24 時間ほどかかります。プロジェクトや環境（本番・検証）ごとにコストを分けたい場合は、早い段階でタグ付けの運用を決めておくことで分析しやすくなります。

コスト配分タグの使用

タグだけでは表現しにくい「複数アカウントと複数タグをまとめてひとつのチーム扱いにする」といった分類は、AWS Cost Categories でルールを定義しておくと、その分類軸で Cost Explorer をグループ化できます。

3.3. コストの種類

Cost Explorer では、同じ利用実績を複数の集計方法で表示できます。どれを見ているかで金額が変わるため、違いを押さえておきます。設定は右側の「詳細オプション」の「コストの集計方法」で切り替えます。

種類

概要

使いどころ

非ブレンドコスト（Unblended）

利用に対して発生した金額。既定の表示。グループ化で「請求タイプ」を選ぶと割引が別項目になる

通常はこれで十分

非ブレンド純コスト（Net Unblended）

割引適用後のコスト

割引後の実際の負担額を見たい

ブレンドコスト（Blended）

一括請求（Organizations）内で、使用量に応じた単価を平均化したコスト

組織全体で平均するといくらか、という見方をしたい

償却コスト（Amortized）

RI / Savings Plans の前払い・月額料金を期間に按分した実質コスト

前払いした月だけ跳ね上がるのを避け、実質的な負担を平準化したい

償却純コスト（Net Amortized）

償却コストに、RI のボリューム割引などの割引も反映したコスト

割引込みの実質負担を見たい

このほか、クレジット、返金、税金、前払い金といった項目は、表示に含めるかどうかをチェックボックスで切り替えられます。純粋な利用料だけを見たいときはクレジットや税金を除外します。

3.4. コスト予測

期間の終了日を未来の日付にすると、Cost Explorer は過去の使用実績をもとに予測値を表示します。月別の粒度では最長 18 か月先まで、日別の粒度では 3 か月先まで指定でき、予測値には 80 % の予測区間が併記されます。

コスト予測有効化確認

コスト予測日別

予測を使ううえでの注意点は次のとおりです。

  • グループ化を指定したグラフでは予測を表示できません。予測を見るときはグループ化を外します
  • 請求サイクルが 1 回分に満たない新しいアカウントなど、データが足りない場合は予測が表示されません
  • 組織にメンバーアカウントを追加した直後は、新しい支出パターンが分析されるまで予測に反映されません

予測はあくまで過去の傾向の延長です。利用量の変動が大きいワークロードや、新しいサービスを使い始めた直後は、実績と大きくずれることがあります。予測の細かい数字を追うよりも、「このままだと月末におおよそいくらになりそうか」を早めに把握する用途に向いています。しきい値を決めて自動で通知したい場合は、AWS Budgets の予測ベースのアラートを組み合わせます。

3.5. レポートの保存とブックマーク

Cost Explorer には、月別コスト（サービス別）、日別コスト、RI・Savings Plans の使用率とカバレッジなど、あらかじめ用意されたレポートがあります。これらを出発点にフィルターやグループ化を調整し、画面右上の「レポートライブラリに保存」で名前を付けて保存できます。

もうひとつ覚えておくと便利なのが、表示条件が URL のクエリパラメータに反映される点です。よく見る条件の画面をブラウザのブックマークに登録しておけば、次回はその条件のまま開けます。

Cost Explorer の設定をブックマークまたはお気に入りとして保存する

ここまでの機能を、よくある場面に当てはめてみます。画面の操作手順は変更されることがあるため、考え方の流れとして読んでください。

4.1. ケース 1：先月のコストが急に増えた

「先月の請求が想定より多い」ときは、次の順に絞り込みます。

  1. 期間を「過去 3 か月」、粒度を「月別」、グループ化を「サービス」にして、どのサービスが増えたかを特定する（例：EC2 - Other が増加）
  2. そのサービスだけをフィルターで絞り、粒度を「日別」に変えて、いつから増えたかを見る（例：月の途中から急増）
  3. グループ化を「使用タイプ」に変えて、何に対する料金かを見る（例：NatGateway-Bytes が増加していれば、NAT Gateway 経由の通信量が原因の可能性）
  4. グループ化を「連結アカウント」「リージョン」に変えて、どこで起きているかを絞る

原因の仮説が立ったら、CloudWatch メトリクスや VPC フローログなど、サービス側の情報で裏付けを取ります。Cost Explorer は「どこで何が増えたか」を示すところまでで、「なぜ」はリソース側で確認するのが基本です。

4.2. ケース 2：プロジェクト・環境ごとのコストを知りたい

「本番と検証でいくらかかっているか」を見たい場合は、コスト配分タグを使います。

  1. リソースに Project や Env といったタグを付ける
  2. 請求コンソールの「コスト配分タグ」で、そのタグ キーを有効化する
  3. Cost Explorer のグループ化で、そのタグを選ぶ

有効化直後は反映まで時間がかかります。また、タグが付いていないリソースのコストは「タグなし」としてまとまって表示されます。詳細オプションの「タグ付けされていないリソースのみを表示」を使うと、タグ付けが漏れているリソースの費用を洗い出せます。

4.3. ケース 3：夜間に検証環境を止めた効果を確かめる

「夜間停止の仕組みを入れたので、効果を確認したい」場合は、時間単位の粒度が役立ちます。

  1. 管理アカウントでコスト管理の設定を開き、時間単位の粒度を有効化する（反映まで最大 48 時間）
  2. 粒度を「時間別」にして、サービスを EC2 に絞る
  3. 停止時間帯にコストが下がっているかを確認する

確認が済んだら、時間単位の粒度は無効化して課金を止めておきます。恒常的な効果の確認は、日別・月別の粒度で前月比を見れば十分なことが多いです。

5.1. 時間単位・リソースレベルの粒度

既定の粒度は月別と日別です。より細かく見たい場合、コスト管理の設定（管理アカウントで操作）から、次の粒度を有効化できます。

  • すべての AWS サービスの時間単位のデータ（リソースレベルなし）
  • EC2 インスタンスのリソースレベルの時間単位のデータ
  • サービスを選択したリソースレベルの日別データ

時間単位のデータとリソースレベルのデータは、直近 14 日分を参照できます。リソースレベルのデータでは、EC2 の個々のインスタンス ID などが確認できます。設定の反映には最大 48 時間かかり、保存後 48 時間は再変更できません。

時間単位の粒度は有料で、使用量レコード 1,000 件あたり月額 0.01ドル（1 レコードあたり 0.00000033ドル）が発生します。バッチ処理の実行時間帯を特定したい、といった短期の調査で有効にし、不要になったら無効化する使い方が無難です。

なお、月次の粒度で最大 38 か月前まで遡れる「マルチイヤーデータ」も、同じ設定画面から有効化できます。

5.2. Reserved Instances / Savings Plans の推奨

Cost Explorer は、過去の利用実績を分析して、リザーブドインスタンスと Savings Plans の購入推奨を出します。オンデマンドで動かし続けているリソースについて、どのプランをどれだけ購入すると、どの程度の割引が見込めるかが提示されます。

推奨の計算には、直近 7 日・30 日・60 日のいずれかのルックバック期間を選べます。推奨内容は定期的に更新され、支払いアカウント単位・メンバーアカウント単位のどちらでも確認できます。実際に購入する前に、対象ワークロードを今後も同じ規模で使い続ける見込みがあるかを確認しておきます。

5.3. Cost Explorer API

コンソールで見ている分析結果は、Cost Explorer API 経由でも取得できます。代表的な操作は次のとおりです。

API

用途

GetCostAndUsage

期間・粒度・グループ化を指定してコストと使用量を取得

GetCostForecast

指定期間のコスト予測を取得

GetSavingsPlansPurchaseRecommendation

Savings Plans の購入推奨を取得

API の呼び出しは、プライマリ請求ビューに対するリクエスト 1 件ごとに 0.01ドルが発生します。結果がページ分割される場合は、ページ単位で課金される点に注意します。日次でコストを Slack に通知する、社内ダッシュボードに取り込む、といった自動化で利用します。

5.4. Amazon Q Developer で自然言語分析する

2026 年 4 月に、Amazon Q Developer を利用した自然言語クエリが Cost Explorer に追加されました（追加料金なし）。「先月コストが最も増えたサービスは何か」といった質問を、おすすめの質問や「質問する」ボタンから入力すると、Cost Explorer のグラフ・表・フィルター・グループ化・期間が回答に合わせて自動で更新されます。また、各レポートの「Amazon Q で分析」を選ぶと、コストの傾向、主な要因、異常についての説明を得られます。フィルターやグループ化の設定に慣れていなくても、聞きたいことを文章で投げれば分析を始められます。

AWS Cost Explorer が Amazon Q を利用した自然言語クエリ機能を導入

使用例

実際に次の 4 つの質問を試しました。いずれも画面右側の Cost Explorer が、回答に合わせて期間やグループ化を自動で切り替えます。回答の下には、どのような条件でデータを取得したか（期間、粒度、指標、フィルター、グループ化）が表示されます。

Q1. 先月最もコストが増えたサービスは何ですか

「前月比で増えたサービス」を、手動の比較操作なしで特定できます。

Q2. 過去 3 か月のサービス別コストを教えてください

期間を「過去 3 か月」、グループ化を「サービス」にした画面（3.1 の手順）が、質問ひとつで表示されます。増減の傾向も文章でまとめてくれます。

Q3. 今月の予測コストと、その要因を教えてください

予測額（約 60.66 ドル）と 80 % の予測区間、サービス別の内訳が表で返ってきました。この質問だけは、右側のグラフが空になります。サービス別の内訳を求めるためにグループ化が指定され、グループ化中は予測を表示できない（3.4）ためです。内訳は回答の表で確認します。

Q4. リージョン別のコストを教えてください

リージョンごとの偏りが一目で分かります。

回答は生成 AI によるもので、画面にも「回答を確認する必要がある場合があります」と表示されます。実際に Q4 では、回答の表の金額（東京リージョン 72.18 ドルなど）が、右側のグラフの金額（東京 11.67 ドル）と一致していませんでした。また Q1 と Q2 でも、集計条件の違い（クレジットの扱いなど）により、合計額が異なって見えます。数字を使うときは、回答の文章だけでなく、右側のグラフと表、そして取得条件を確認してください。

Cost Explorer は、素早く傾向をつかむためのツールです。厳密な分析や通知は、隣接するサービスと役割を分担します。

AWS Cost and Usage Report（CUR、現在は Data Exports として提供）は、課金の行レベルの詳細をすべて S3 に出力します。1 円単位でリソースを突き合わせたい、独自の集計軸で長期分析したい、という場合は CUR を Amazon Athena や Amazon QuickSight と組み合わせます。Cost Explorer は CUR と同じデータセットを、対話的に見やすくした画面、という位置づけです。

AWS Budgets は、月額予算に対して実績や予測が一定のしきい値を超えたときに通知します。コスト異常検出は、機械学習で普段と異なる支出パターンを検知します。可視化は Cost Explorer、しきい値による通知は Budgets、想定外の急増の検知は異常検出、と使い分けます。

AWS Cost Explorer は、AWS のコストと使用量を期間・粒度・グループ化・フィルターの組み合わせで可視化し、原因を掘り下げていくためのツールです。過去 13 か月の実績と 18 か月先までの予測を、コンソールから無料で参照できます。

運用を行う上で、重要な点は次の 3 点です。

  • アカウント作成後、早めに「IAM ユーザー/ロールによる請求情報へのアクセス」を有効化し、コスト配分タグの運用も決めておく
  • 見ている金額が非ブレンド・ブレンド・償却のどれかを意識する
  • 時間単位・リソースレベルの粒度と API は課金対象。短期調査や自動化で使い、常用しない

より詳細な行レベル分析は CUR、閾値通知は AWS Budgets、急増の検知はコスト異常検出と、目的に応じて組み合わせます。
