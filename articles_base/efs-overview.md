## EFS とは

フルマネージド型ファイルストレージサービスで、複数のコンピューティングリソースから同時にマウントできる共有ファイルシステムとしてよく利用されます。EC2だけでなく、Lambda、ECS、EKSなどからも使えます。

ネットワークファイルシステムバージョン 4 (NFSv4.1 および NFSv4.0) プロトコルを使用し、Linuxワークロード向けに設計されています。
Windows Serverの場合は、Amazon FSx for Windows File Serverを利用します。

## EBS・S3・FSx との違い

AWSのストレージは、データの扱い方で使い分けます。

| サービス | 種類 | 特徴 | 主な用途 |
|----------|------|------|----------|
| EFS | ファイルストレージ（NFS） | 複数のクライアントから同時にマウントできる。Linux向け | 複数サーバーで共有するコンテンツ、Lambda・コンテナの共有ストレージ |
| EBS | ブロックストレージ | 単一のEC2インスタンスから低レイテンシーでアクセス | OSやデータベースのディスク |
| S3 | オブジェクトストレージ | APIでどこからでもアクセスできる | 静的ファイル、バックアップ、データレイク |
| FSx for Windows File Server | ファイルストレージ（SMB） | Windows向けの共有ファイルサーバー | Windowsのファイル共有 |

「ファイルシステムとして複数のLinuxインスタンスから同時に読み書きしたい」なら EFS、「1台のEC2のディスク」なら EBS、「APIで出し入れするデータ」なら S3 が基本の選び方です。

## EFS の基本構成

<!-- Duration: 0:01:30 -->

![efs](/images/efs/efs.png)

- マウントターゲット
  - EC2から接続するエンドポイントのことで、実体はENIであり、プライベートIPアドレスが割り当てられます。
  - AZに1つだけ作成できます。
  - セキュリティグループでアクセス制御を行います（詳細は「セキュリティ」を参照）。
  - パブリックIPアドレスは持てません。VPC内、接続済みのVPC、Direct ConnectやVPN経由のオンプレミスから利用します。
- DNS名
  - EC2から接続する場合はDNS名を指定します。
  - DNS名は2種類あります。
    - ファイルシステム： `file-system-id.efs.aws-region.amazonaws.com`
      - 同一AZのマウントターゲットのIPを返します。別AZのIPは返しません。
    - マウントターゲット： `availability-zone.file-system-id.efs.aws-region.amazonaws.com`
      - 別AZからでも参照できます。
- 別のVPCから接続したい場合は、VPCピアリングやTransitGatewayなどで事前に接続しておきます。

## ファイルシステムのタイプ

![efs-filesystem-type](/images/efs/efs-filesystem-type.jpg)

1. **リージョン**
    - 3つ以上のアベイラビリティゾーンにデータを複製
    - 99.999999999%（11ナイン）の耐久性
    - 頻繁にアクセスされるデータ向け

2. **1ゾーン**
    - 単一AZでの運用によるコスト最適化
    - 99.999999999%（11ナイン）の耐久性
    - AZ障害には耐えられないため、開発環境やバックアップ取得済みのデータ向け

## ストレージクラス

1. **標準**
    - SSD
    - 頻繁にアクセスされるデータ

2. **低頻度アクセス (IA,Infrequent Access)**
    - アクセス頻度の低いデータ向け
    - 四半期ごとに数回しかアクセスされないデータ

3. **EFS アーカイブ**
    - 1 年に数回しかアクセスされないデータ

## ライフサイクルポリシー

![efs-lifecycle-settings](/images/efs/efs-lifecycle-settings.jpg)

S3バケットのライフサイクルと同様に低頻度アクセスのデータを低コストのストレージクラスに移動させることでコストを最適化できます。
デフォルトでは、標準ストレージクラスで30日間アクセスのないファイルがIAに、90日間アクセスのないファイルがアーカイブに移ります。
S3と違い、EFSでは最初のアクセス時に標準ストレージクラスへ戻す設定も選べます（デフォルトでは戻しません）。

![efs-lifecycle](/images/efs/efs-lifecycle.jpg)

## パフォーマンスモードとスループットモード

[Amazon EFS のパフォーマンス](https://docs.aws.amazon.com/ja_jp/efs/latest/ug/performance.html)は、パフォーマンスモードとスループットモードの組み合わせで決まります。

パフォーマンスモードは、汎用と最大 I/O の2種類です。

- 汎用: デフォルトで推奨。レイテンシーが最も低く、1ゾーンのファイルシステムでは汎用のみ使えます
- 最大 I/O: 旧世代。レイテンシーが高くなるため、すべてのファイルシステムで汎用を推奨。1ゾーンと Elastic スループットでは使えません

スループットモードは3種類です。

| モード | 特徴 | 向いているワークロード |
|--------|------|------------------------|
| Elastic | デフォルトで推奨。ワークロードに応じて自動でスループットが増減し、指定は不要 | 負荷が読めない・変動が大きい |
| Provisioned | ファイルシステムのサイズと無関係に、スループットを固定値で指定。指定量に応じて課金 | 必要な性能が分かっている・持続的に必要 |
| Bursting | 標準ストレージの容量に比例（1GiBあたり 50KiB/秒）。バーストクレジットを消費して一時的に上回る | 容量に応じたスループットで足りる |

Provisioned に切り替えた直後の24時間は、Elastic・Bursting への変更やスループット量の引き下げができません。設定は慎重に行います。

## セキュリティ

EFSへのアクセスは、次の層で制御します。

- ネットワーク: マウントターゲットのセキュリティグループで、EC2のセキュリティグループからのTCP 2049番ポート（NFS）を許可します。EC2側は、マウントターゲットのセキュリティグループへの2049番ポートのアウトバウンドを許可します。
- IAM: IAMポリシーとファイルシステムポリシーで、操作を許可するIAMプリンシパルを制限します。マウント時に `iam` オプションを指定すると、IAM認証を使えます。
- POSIXパーミッション: ファイルやディレクトリのユーザー・グループ・パーミッションで、NFSレベルのアクセスを制御します。
- アクセスポイント: アプリケーションごとにルートディレクトリとPOSIXユーザーを固定します（次の節を参照）。

暗号化は、保管時と転送中の2つがあります。

- 保管時の暗号化: AWS KMSキーで暗号化します。AWS所有のキー（`aws/elasticfilesystem`）か、カスタマー管理キーを選べます。
- 転送中の暗号化: マウント時に `tls` オプションを指定すると、TLSで暗号化します。

:::message alert
保管時の暗号化は、ファイルシステムの作成時にしか設定できません。作成後に暗号化なし→ありへ変更することはできません。マネジメントコンソールではデフォルトで有効ですが、AWS CLI・API・SDKで作成する場合は明示的に有効化が必要です。暗号化なしで作成してしまった場合は、EFSレプリケーションで暗号化済みの新しいファイルシステムへコピーします。
:::

## アクセスポイント

アクセスポイントは、EFSファイルシステムへのアプリケーション専用の入口です。次の2つを強制できます。

- ルートディレクトリ: アクセスポイント経由のクライアントは、指定したディレクトリ以下しか参照できません
- POSIXユーザー: アクセスポイント経由のリクエストすべてに、指定したユーザー・グループを適用します

IAMポリシーと組み合わせると、「このアプリケーションはこのアクセスポイントしか使えない」という制御ができます。1つのファイルシステムを複数のアプリで共有しつつ、データを分けられます。

マウントヘルパーでは、アクセスポイントIDを指定してマウントします（マウントターゲットの作成が前提です）。

```sh
sudo mount -t efs -o tls,accesspoint=fsap-abcdef0123456789a file-system-id: efs/
```

## EC2での利用

EFSマウントヘルパー（`amazon-efs-utils` パッケージ）を使用します。事前にEC2へインストールしておきます。

```sh
# マウントするディレクトリを作成します
sudo mkdir efs

# ファイルシステムIDを指定してマウントします
sudo mount -t efs file-system-id efs/

# 転送中の暗号化（TLS）を有効にしてマウントする場合
sudo mount -t efs -o tls file-system-id efs/
```

この方法だと、再起動するとマウントが外れます。永続化するには `/etc/fstab` に追記します。

```text
file-system-id:/ efs-mount-point efs _netdev,noresvport,tls 0 0
```

- `_netdev`: ネットワークが有効になるまでマウントを待ちます。指定しないと、起動時にインスタンスが応答しなくなることがあります
- `noresvport`: 再接続時に新しいTCPソースポートを使い、ネットワーク復旧後も途切れず接続できます
- `tls`: 転送中の暗号化を有効にします

追記後は `sudo mount -fav` で、`/etc/fstab` の記述を検証できます。

## EC2以外からの利用

EFSはEC2以外からもマウントできます。

- Lambda: [関数の設定でEFSファイルシステムを指定](https://docs.aws.amazon.com/ja_jp/lambda/latest/dg/configuration-filesystem-efs.html)します。関数をVPCに接続しておく必要があります。マウント先のローカルパスは `/mnt/` で始めます。アクセスポイントの利用が推奨されており、実行ロールには `elasticfilesystem:ClientMount`（書き込みには `elasticfilesystem:ClientWrite` も）が必要です
- ECS（EC2・Fargate）: タスク定義でEFSボリュームを指定します
- EKS: EFS CSIドライバーを使い、Podから利用します（EC2・Fargate）
- SageMaker: トレーニングジョブやStudioのホームディレクトリで利用できます
- オンプレミス: Direct ConnectまたはVPN経由でマウントできます。既存データの移行には AWS DataSync が使えます

Lambdaのようにサイズや永続性に制限がある環境で、大きなファイルや共有データを扱いたい場合に便利です。

## モニタリングとトラブルシューティング

主要なCloudWatchメトリクスは次のとおりです。

- PercentIOLimit
  - ファイルシステムが汎用パフォーマンス モードの I/O 制限にどれだけ近づいているか
- BurstCreditBalance
  - ファイルシステムのバーストクレジットの数（Bursting スループットモードのみ）。バースト容量の80%以上を使っている、またはクレジットが枯渇する場合は、Elastic か Provisioned への変更を検討します
- StorageBytes
  - EFS ストレージクラスに保存されているデータの量を含む、ファイルシステムのサイズ (バイト単位)

## コスト削減のベストプラクティス

- IAストレージクラスを使う
- 必要な性能に合ったスループットモードを選ぶ（負荷が読めないなら Elastic）

## 📖 まとめ

- 複数のLinuxインスタンスから同じファイルを読み書きしたいなら、EFSを選ぶ。Windowsの場合はFSx for Windows File Server
- 開発環境など、AZ障害を許容できる用途なら1ゾーンでコストを抑えられる
- 長期間触らないデータが多いなら、ライフサイクルポリシーでIA・アーカイブへ移す。移行までの日数はデフォルトの30日・90日から調整できる
