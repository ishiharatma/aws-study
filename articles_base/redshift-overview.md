## Amazon Redshift とは

ペタバイト規模のデータを扱えるフルマネージドのデータウェアハウス（DWH）サービスです。大量の構造化データに対する複雑な集計・分析クエリを高速に処理することに特化しています。

[Amazon Redshift サービス概要](https://aws.amazon.com/redshift/)

[Amazon Redshift ドキュメント](https://docs.aws.amazon.com/redshift/latest/mgmt/welcome.html)

[Amazon Redshift よくある質問](https://aws.amazon.com/redshift/faqs/)

[Amazon Redshift の料金](https://aws.amazon.com/redshift/pricing/)

OLTP（オンライン取引処理）向けの RDS や Aurora とは異なり、Redshift は OLAP（オンライン分析処理）、つまり大量データの読み取り・集計を伴う分析ワークロード向けに設計されています。

## アーキテクチャの基本

### 列指向ストレージと MPP

Redshift は、行ではなく列単位でデータを格納する「列指向ストレージ」を採用しています。分析クエリは特定の列だけを集計することが多いため、必要な列だけを読み込むことで I/O を削減できます。また、複数のコンピュートノードにデータとクエリ処理を分散して並列実行する MPP（Massively Parallel Processing）アーキテクチャにより、大量データに対するクエリを高速化しています。

### ノードタイプ

クラスターは、クエリの受付や実行計画の作成を行うリーダーノードと、実際にデータを保持し処理を行う複数のコンピュートノードで構成されます。コンピュートノードには、コンピュートとストレージが一体になった DC2（高いコンピュート性能重視）と、コンピュートとストレージを分離してスケーラブルにした RA3（大容量データ・柔軟なスケーリング重視）などのタイプがあります。

## Provisioned クラスターと Redshift Serverless

Redshift には 2 つの利用形態があります。

- Provisioned クラスター：ノードタイプとノード数を自分で選択し、クラスターとして常時起動しておく従来型の利用形態。予測可能な安定したワークロードに向く
- Redshift Serverless：RPU（Redshift Processing Unit）という単位でコンピュートリソースを自動的にプロビジョニング・スケーリングする形態。ワークロードがアクティブな間だけ課金され、利用頻度が不規則な分析基盤や、開発・検証環境に向く

## 主な機能

### Redshift Spectrum

クラスターにデータをロードすることなく、Amazon S3 上に置いたデータに対して直接 SQL クエリを実行できる機能です。頻繁にアクセスするデータはクラスターに、あまりアクセスしない大容量データは S3 に置く、といった使い分けができます。

### Concurrency Scaling

急なクエリ集中が発生した際に、追加のクラスターリソースを自動的に、かつ透過的に立ち上げて処理をさばく機能です。一定の無料利用枠があり、それを超えた分のみ課金されます。

### ゼロ ETL 統合

Aurora や RDS for MySQL などのトランザクションデータベースのデータを、ETL パイプラインを構築することなく、ほぼリアルタイムで Redshift に反映できる統合機能です。分析のためのデータ連携パイプラインの構築・運用の手間を減らせます。

### Redshift ML

SQL 文だけで Amazon SageMaker と連携した機械学習モデルの作成・トレーニング・推論を行える機能です。データサイエンティストでなくても、使い慣れた SQL の延長で予測分析を行えます。

## データ分散とソートキー

クエリ性能を最適化するために、テーブルには「分散キー」と「ソートキー」を設定します。分散キーはテーブルの行を各コンピュートノードにどう配置するかを決め、関連するテーブル同士を同じノードに配置することで、ノード間のデータ転送（シャッフル）を減らせます。ソートキーは、ディスク上でのデータの並び順を決め、範囲検索やフィルタリングを高速化します。

## セキュリティ

VPC 内への配置、保管時の KMS 暗号化、通信の SSL/TLS 暗号化に加え、行レベル・列レベルのアクセス制御、AWS Lake Formation と連携したきめ細かいデータアクセス制御など、エンタープライズ向けのセキュリティ機能が備わっています。

## ユースケース

- 全社的なデータウェアハウスとしての BI・レポーティング基盤
- 複数システムから集約したログ・トランザクションデータの大規模分析
- Amazon QuickSight などの BI ツールと連携したダッシュボード構築
- S3 データレイクと組み合わせたレイクハウスアーキテクチャ
- SQL ベースでの機械学習予測（Redshift ML）

## 料金

Provisioned クラスターはノードタイプ・ノード数に応じた時間課金、Redshift Serverless は消費した RPU 時間（秒単位、60 秒の最低利用）に応じた課金です。いずれもストレージ使用量に応じた料金が別途発生します。Concurrency Scaling や Redshift Spectrum など、機能ごとに個別の課金体系があるため、詳細は [Amazon Redshift の料金ページ](https://aws.amazon.com/redshift/pricing/) を確認してください。

## 他サービスとの使い分け

- Amazon Athena：S3 上のデータに対してサーバーレスにアドホッククエリを実行したい場合。インフラ管理が不要な反面、頻繁な大規模分析には Redshift の方がコスト効率・パフォーマンスに優れることが多い
- Amazon RDS／Aurora：OLTP（日々のトランザクション処理）向け。Redshift は OLAP（分析）向けであり、役割が異なる
- Amazon EMR：Hadoop／Spark エコシステムを使った大規模な分散データ処理基盤が必要な場合

## メリット

- 列指向ストレージと MPP により、大規模データに対する分析クエリが高速
- Serverless により、利用頻度が不規則なワークロードでもコストを抑えやすい
- Redshift Spectrum やゼロ ETL 統合により、S3 やトランザクション DB とのデータ連携が容易
- SQL の知識だけで機械学習まで扱える（Redshift ML）

## デメリット・注意点

- OLTP のような高頻度の単純な読み書きには向いておらず、DWH 用途に特化している
- 分散キー・ソートキーの設計を誤ると、期待した性能が出ないことがある
- Provisioned クラスターは常時起動が前提のため、利用が少ない時間帯もコストが発生する（Serverless で緩和可能）
- 大量データを扱う性質上、他の DB サービスに比べてコスト規模が大きくなりやすい

## 📖 まとめ

Amazon Redshift は、大量データに対する複雑な分析クエリを高速に処理するために設計されたデータウェアハウスです。Provisioned と Serverless という 2 つの利用形態、Redshift Spectrum によるデータレイク連携、ゼロ ETL 統合など、分析基盤としての要件に応じた機能が揃っています。OLTP 用途の RDS・Aurora や、サーバーレスなアドホック分析向けの Athena とは役割が異なるため、ワークロードの性質に応じて使い分けることが重要です。
